# S10: foto do app como anexo nativo do Claude Code

**Data**: 2026-10-01
**Versões**: Claude Code 2.1.286 · Herdr 0.9.3 · macOS 27
**Resultado**: aprovado com ajustes

## Pergunta

Como fazer a foto enviada pelo app chegar ao Claude como anexo nativo (`[Image #N]`, bloco `image` em base64 no transcript), como o Moshi faz, em vez do marcador `[imagem: <caminho>]` seguido de um `Read`. E como o transcript grava cada caso, para a bolha mostrar a imagem a partir dele.

## Resposta

Não precisa do clipboard. O `agent.prompt` do Herdr, que o `mochad` já usa, cola o texto como bracketed paste. Nessa colagem, o Claude Code converte em anexo nativo cada linha que contém só caminhos de imagem existentes. Basta o app trocar a linha `[imagem: <caminho>]` por uma linha com o caminho puro do upload.

O Claude Code então:
- lê o arquivo na hora da colagem;
- reduz a imagem para no máximo 2000 px;
- grava o base64 na linha do prompt;
- grava o caminho de origem numa linha `isMeta` logo depois.

Isso funciona também com a mensagem na fila. Para a bolha, a fonte confiável é o bloco `image` do transcript. Ele também cobre as imagens coladas direto no terminal, que hoje aparecem como "📎".

## Decisões

Propostas; as marcadas com (João) dependem dele no contrato.

1. **Envio** (§6.5): o upload por `POST /v1/upload` continua. O texto do `sendPrompt` troca cada linha `[imagem: <caminho>]` por uma linha só com o caminho absoluto, na ordem das miniaturas. O `agent.prompt` cola, e o Claude Code anexa. Fica sem clipboard, sem tecla extra e sem mudança no cliente do Herdr.
2. **Plano B**: se uma versão do Claude Code deixar de converter, o caminho fica no texto e o Claude ainda consegue abri-lo com `Read`. Um teste `.integration` da conversão entra no `scripts/check-claude-update.sh` (§Atualização do Claude Code do AGENTS.md).
3. **Texto da bolha** (§3.2): no `userPrompt` com `imagePasteIds`, depois do `PastedContent.unwrapped`, saem do texto os `[Image #N]` cujo `N` está em `imagePasteIds`, junto com o espaço que vem depois. O `imageCount` continua sendo o número de blocos `image`. Um `[Image #N]` fora de `imagePasteIds` fica.
4. **Origem da imagem da bolha** (João): o bloco `image` do transcript. Há duas formas de levá-lo ao app:
   - **A, materializar**: ao ler a linha, o daemon grava cada bloco num cache endereçado por conteúdo (`~/Library/Caches/com.joaoalves.mocha/transcript-images/<sha256>.<ext>`) e põe esse caminho no `imagePaths`. Todo o resto da fase imagens fica igual: filtro de existência, `/v1/image`, cache do app e tela cheia. O custo é guardar os bytes duas vezes em disco, o que pede uma regra de limpeza.
   - **B, rota no transcript**: `GET /v1/transcript-image?session=<id>&line=<uuid>&index=<n>&max=` lê o bloco direto do JSONL, e o `ChatItem` passa a levar uma referência em vez de um caminho. Não duplica bytes, mas exige saber em que posição do arquivo fica cada linha (os arquivos passam de 17 MB) e cria um segundo tipo de referência no protocolo e no app.
5. **Histórico**: os marcadores `[imagem: …]` antigos continuam sendo lidos (`ImageMarkers`). As imagens coladas no terminal, antigas e novas, ganham miniatura pela decisão 4.
6. **Redução no app** (João, opcional): o app reduz para 2048 px e o Claude Code reduz de novo para 2000 px. Baixar o `ImageReduction.maximumPixelSize` para 2000 evita a segunda redução. Não foi testado se o Claude Code recomprime um JPEG que já está em 2000 px.

## Armadilhas

- `herdr pane send-text` sem `ESC[200~ … ESC[201~` digita o caminho, e o Claude Code não converte. O `agent.prompt` já cola.
- O caminho precisa estar numa linha própria, ou separado só por espaço de outros caminhos. Caminho no meio de frase continua texto, e arquivo inexistente também.
- A conversão acontece na colagem, então o arquivo precisa existir nesse instante. Depois disso os bytes estão no transcript, e a expiração do `uploads/` em 7 dias deixa de apagar a imagem da conversa.
- Os ids de `[Image #N]` são da sessão e avançam até em colagens apagadas antes do envio: no laboratório, os ids 3 a 16 foram consumidos por colagens limpas com `ctrl+u`. Use sempre o `imagePasteIds` da própria linha, nunca uma contagem.
- Com a mensagem na fila, o `enqueue` só tem o texto com o chip. O bloco `image` só aparece quando a mensagem sai da fila, numa linha `user` com `promptSource: "queued"`, e a bolha pendente espera até lá.
- O caminho de origem na linha `isMeta` de uma imagem colada no terminal aponta para um cache do Claude Code que é apagado. Não serve como fonte.
- Uma linha com imagem colada pode passar de 1 MB (S1). Quem extrai os blocos não deve manter o base64 nos `ChatItem`.
