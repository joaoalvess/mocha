# W1: SSH com a chave da Secure Enclave e `direct-tcpip`

**Data**: 2026-09-28
**Versões**: Citadel 0.12.1 (ae8562f) · swift-nio-ssh do fork `Wellz26/swift-nio-ssh` 0.3.7 (d88989f) · swift-nio 2.103.0 · swift-crypto 3.15.1 · iOS 27 SDK · Xcode 27 (Swift 6.4)
**Resultado**: aprovado com ajustes (compilado; a chamada real contra o Mac fica para o WP-W5, com o B5)

## Pergunta

O Citadel autentica com uma chave P-256 da Secure Enclave, abre canais `direct-tcpip` e permite repassar bytes de um `NWListener` em `127.0.0.1` nos dois sentidos, em Swift 6 com strict concurrency?

## Resposta

Sim, com um delegate de autenticação próprio. O Citadel não tem um `SSHAuthenticationMethod` que aceite a chave da Secure Enclave, mas `SSHAuthenticationMethod.custom(_:)` recebe qualquer `NIOSSHClientUserAuthenticationDelegate`, e o NIOSSH do fork tem `NIOSSHPrivateKey(secureEnclaveP256Key:)`. O `direct-tcpip` sai pronto de `SSHClient.createDirectTCPIPChannel`, e o canal embrulhado num `NIOAsyncChannel<ByteBuffer, ByteBuffer>` se liga a um `NWConnection` sem `@unchecked Sendable`. O probe compila e está na tela de Debug `SSHProbeScreen`.

## Evidências

Código em `App/Sources/Debug/`:

- `SSHProbeKey.swift`: `SSHProbeKeyStore.loadOrCreate()` e `SSHProbeSigningKey` (Secure Enclave no aparelho, P-256 em software só no simulador).
- `SSHProbeConnection.swift`: `SSHProbePublicKeyAuthentication`, `SSHProbeHostKeyPolicy` e o actor `SSHProbeConnection`.
- `SSHProbePortForwarder.swift`: o actor `SSHProbePortForwarder` e o `SSHProbeBridge`.
- `SSHProbeScreen.swift`: formulário (host, usuário, portas, chave do host fixada), gerar e copiar a chave, conectar e um `WKWebView` em `http://127.0.0.1:<porta local>/`.

API exata usada (lida nos checkouts de `~/Library/Caches/com.joaoalves.mocha/SourcePackages/checkouts`):

| Uso | API |
|---|---|
| Chave SE → SSH | `NIOSSHPrivateKey(secureEnclaveP256Key: SecureEnclave.P256.Signing.PrivateKey)`, em `#if canImport(Darwin)` (`swift-nio-ssh/Sources/NIOSSH/Keys And Signatures/NIOSSHPrivateKey.swift:55`); assina `ecdsa-sha2-nistp256` |
| Linha do `authorized_keys` | `String(openSSHPublicKey: privateKey.publicKey)` (`NIOSSHPublicKey.swift:607`) + comentário |
| Autenticação | `SSHAuthenticationMethod.custom(_ delegate: NIOSSHClientUserAuthenticationDelegate)`; o delegate oferece `NIOSSHUserAuthenticationOffer(username:serviceName: "", offer: .privateKey(.init(privateKey:)))` uma vez, só se `availableMethods.contains(.publicKey)` |
| Chave do host | `SSHHostKeyValidator.custom(NIOSSHClientServerAuthenticationDelegate)`; compara `String(openSSHPublicKey: hostKey)` com a fixada |
| Conexão | `SSHClient.connect(host:port:authenticationMethod:hostKeyValidator:reconnect: .never, connectTimeout: .seconds(10))` (`Citadel/Sources/Citadel/Client.swift:278`) |
| Canal | `SSHClient.createDirectTCPIPChannel(using: SSHChannelType.DirectTCPIP(targetHost: "127.0.0.1", targetPort:, originatorAddress:), initialize: (Channel) -> EventLoopFuture<Void>) async throws -> Channel`; o Citadel já instala o `DataToBufferCodec` e liga `allowRemoteHalfClosure` |
| Canal async | no `initialize`: `NIOAsyncChannel<ByteBuffer, ByteBuffer>(wrappingChannelSynchronously: channel, configuration: .init(isOutboundHalfClosureEnabled: true))`, que sai por um `Mutex` numa classe final `Sendable` |
| Listener | `NWListener` com `requiredLocalEndpoint = .hostPort(.ipv4(.loopback), .any)` ou a porta preferida, `acceptLocalOnly = true`, `allowLocalEndpointReuse = true` |
| Ponte | `channel.executeThenClose { inbound, outbound in … }` com dois filhos num task group: `NWConnection.receive` → `outbound.write`, e no EOF `outbound.finish()`; `for try await inbound` → `NWConnection.send`, e no fim `send(content: nil, contentContext: .finalMessage, isComplete: true)` |

Validação:

- `scripts/build-app.sh` → `** BUILD SUCCEEDED **`, sem avisos nos arquivos `SSHProbe*`.
- Primeiro build falhou em Swift 6: `EventLoopPromise<NIOSSHUserAuthenticationOffer?>.succeed` exige `Sendable`, e a oferta não é. Corrigido com `nextChallengePromise.assumeIsolated().succeed(…)` (o NIOSSH chama o delegate no event loop do canal; `assumeIsolated()` confere isso com `preconditionInEventLoop`).
- Sem teste no Mac nem no aparelho: falta o B5 (Remote Login e a chave no `authorized_keys`). A tela não está ligada a um `-preview` porque `LaunchConfiguration.swift` e `RootView.swift` estão fora do diretório dono (diff no relatório).

## Decisões

1. Autenticação por delegate próprio (`SSHAuthenticationMethod.custom`) com `NIOSSHPrivateKey(secureEnclaveP256Key:)` (§9.1).
2. A chave da Secure Enclave usa `[.privateKeyUsage, .biometryCurrentSet]` e `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`; o `dataRepresentation` fica no Keychain como item genérico. O Face ID aparece a cada assinatura, ou seja, a cada nova conexão SSH (§9.1).
3. No simulador (só Debug), chave P-256 em software no mesmo Keychain, com o mesmo formato de linha pública (§9.1).
4. A chave do host é fixada com `SSHHostKeyValidator.custom`; sem chave fixada, a primeira conexão mostra a apresentada (§9.1).
5. `reconnect: .never`: quem reconecta é o app, no ciclo de vida da §9.3.
6. O `PortForwarder` recebe um `ChannelOpener` (`@Sendable (Int) async throws -> NIOAsyncChannel<ByteBuffer, ByteBuffer>`) em vez do `SSHClient`, e assim os testes usam um canal falso (§9.3, WP-W4).
7. `@preconcurrency import Citadel`: o `SSHClient` não é `Sendable` e fica isolado num actor.

## Armadilhas

- `EventLoopPromise.succeed` exige `Sendable` em Swift 6; `NIOSSHUserAuthenticationOffer` não é. Use `promise.assumeIsolated().succeed(…)` dentro do delegate.
- `SSHAuthenticationMethod.p256(username:privateKey:)` aceita só `P256.Signing.PrivateKey` em software, e o `init(username:offer:)` é interno: não há atalho para a Secure Enclave.
- O `createDirectTCPIPChannel` devolve o `Channel` cru; o `NIOAsyncChannel` precisa ser criado dentro do `initialize` (no event loop), por isso sai por um slot com `Mutex`.
- O delegate oferece a chave uma vez e depois devolve `nil`; sem essa trava, uma recusa do servidor levaria a novas ofertas (e novos Face ID) até o servidor fechar a conexão.
- `SecureEnclave.P256.Signing.PrivateKey(accessControl:)` com `.biometryCurrentSet` sem `NSFaceIDUsageDescription` derruba o app na primeira assinatura; o probe confere a chave no Info.plist e devolve um erro antes.

## Limpeza

Nada fora do repositório. O probe grava no Keychain do app os itens do service `com.joaoalves.mocha.ssh-probe`; o botão "Apagar chave" remove. Nenhum build extra além de `build/DerivedData` do worktree.
